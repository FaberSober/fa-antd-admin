# ADR：mobile 多租户工作空间切换

- 状态：🟡进行中
- 日期：2026-09-16
- 范围：`mobile` Uni-app、`fa-core-mobile`、`fa-base-mobile`

## 背景

后端已经提供用户租户列表接口，并通过 `fa-tn-tenant-id` 请求头确定当前租户和校验用户权限。mobile 当前只携带登录 Token，没有租户上下文和切换入口。

参考飞书的工作空间体验，租户切换入口需要同时展示租户标识、当前选中状态和各租户的未读消息数。IM 数据租户隔离和未读数聚合由 [fa-im 租户隔离 ADR](2026-09-16-im-tenant-isolation.md) 负责，本文只定义 mobile 的消费和展示方式。

## 目标

- 登录后加载当前用户可用的租户工作空间。
- 在登录后的主页展示当前租户，并支持切换租户。
- 每个租户展示独立的未读消息角标。
- 后续业务请求统一携带当前租户请求头，避免不同租户数据混用。
- 切换、恢复登录和退出登录时保持租户状态一致。

## 范围边界

- 本文负责 mobile 的租户状态、工作空间 UI、未读数合并和请求上下文。
- `fa-im` 负责消息表租户字段、消息数据隔离和未读数聚合接口，详见对应 ADR。
- 不在本期实现租户创建、邀请成员、租户排序管理和消息 WebSocket 实时角标；实时角标留作后续版本。

## 决策

### 1. 采用“租户工作空间”交互模型

- 每个租户作为一个独立工作空间，使用 Logo、简称或首字母头像识别。
- 工作空间列表展示租户名称、当前选中状态和未读消息数。
- 未读数为 `0` 时隐藏角标，`1-99` 展示实际数量，超过 `99` 展示 `99+`。
- 移动端采用首页顶部当前租户入口，点击后打开基于 Uni-app 原生 `view`、`scroll-view` 的抽屉或底部弹层。
- 不引入第三方选择器依赖；首期不复制桌面端固定左侧竖栏，后续有统一侧边栏时再扩展视觉形态。

### 2. 复用现有租户接口和请求头

- 租户列表使用 `GET /api/base/tn/tenantUser/myTenants`。
- 租户切换不修改登录 Token，也不新增租户表。
- 选中的租户通过 `fa-tn-tenant-id` 传递，服务端继续校验用户是否属于该租户。
- 每租户未读数使用 `fa-im` 提供的跨租户聚合接口：

  ```text
  GET /api/im/core/imConversation/unreadByTenants
  ```

- mobile 分别请求租户信息和未读数，再按 `tenantId` 合并；不按租户逐个切换请求头查询，避免请求串扰和 N+1 请求。

### 3. Core 与 Base 分层

- `fa-core-mobile`：维护当前租户请求上下文，并在公共 request/upload 请求中统一注入 `fa-tn-tenant-id`。
- `fa-base-mobile`：实现租户 API、工作空间类型、Store、登录态集成、持久化和页面交互。
- 业务 Feature 不直接读取或拼接 `fa-tn-tenant-id`。

### 4. 初始化和持久化

- 工作空间 Store 维护 `workspaces`、`currentTenantId`、`currentWorkspace` 和总未读数。
- 当前租户按用户 ID 隔离保存，Key 使用 `fa.mobile.tenant-id.<userId>`。
- 初始化时先清除内存中的当前租户，再请求 `myTenants`，避免失效的旧租户请求头阻断租户列表接口。
- 优先恢复该用户上次选择的有效租户，否则选择接口返回的第一个租户。
- 没有可用租户时清除租户上下文并展示空状态，不继续使用过期租户 ID。
- 未读数可以短时间缓存，但以服务端刷新结果为准；不同租户的页面缓存必须使用租户维度隔离。

### 5. 切换和刷新

- 只允许从已加载且有权限的工作空间列表中选择目标租户。
- 切换成功后更新内存状态、本地存储和 Core 请求上下文。
- 切换不会自动将消息标记为已读。
- 切换后刷新首页、消息入口和当前页面数据；首期可使用 `uni.reLaunch` 清理旧页面状态。
- 租户无权限或已被移除时，清除当前租户并重新选择有效租户，不强制退出登录。

### 6. 未读数刷新

- 首期在登录成功、首页 `onShow`、应用回到前台、租户切换、消息已读和手动刷新时获取未读数。
- 未读数接口失败时保留上次结果，并展示非阻塞错误提示。
- WebSocket 实时增量更新要求 IM 事件携带 `tenantId`，作为后续版本开发。

## 客户端模型

```text
TenantWorkspace {
  tenantId
  tenantName
  tenantShortName
  tenantLogo
  unreadCount
  isAdmin
}
```

跨租户未读数接口返回的 `tenantId/unreadCount` 与租户列表按 ID 合并；缺少未读数时按 `0` 处理，缺少租户信息时不展示该条数据。

## 开发说明

### Core 请求上下文

- 增加当前租户的读写、清理能力。
- 在统一请求和上传请求中注入租户请求头。
- 初始化租户列表前支持临时清除旧租户上下文。

### Base 工作空间 Store

- 增加租户类型、租户列表 API 和未读数 API 封装。
- 负责租户列表与未读数合并、默认租户选择和按用户持久化。
- 接入登录、恢复登录、退出登录和租户失效处理。

### 工作空间 UI

- 首页展示当前租户入口。
- 使用原生页面组件实现带头像、选中态和未读角标的工作空间弹层。
- 切换后刷新页面数据，并避免旧租户页面缓存继续展示。

### 验证

- 验证单租户、多租户、租户失效、切换失败和账号切换场景。
- 验证各租户角标与服务端聚合结果一致。

## 实施顺序

1. 在 `fa-core-mobile` 增加租户上下文和公共请求头注入。
2. 在 `fa-base-mobile` 增加租户类型、租户 API 和工作空间 Store。
3. 接入登录、恢复登录和退出登录流程，完成默认租户选择和按用户持久化。
4. 接入 `fa-im` 跨租户未读数接口并完成数据合并。
5. 在登录后的主页增加原生工作空间入口、列表、选中态和未读角标。
6. 实现租户切换后的页面刷新和缓存隔离。
7. 完成失效租户、无租户和接口失败场景验证。

## 验收标准

- 单租户用户登录后能自动使用该租户。
- 多租户用户能在主页查看工作空间列表并切换租户。
- 每个租户展示与服务端一致的独立未读消息数。
- 租户相关业务请求自动携带 `fa-tn-tenant-id`。
- 刷新或重新打开 App 后保留上次有效选择。
- 更换账号后不会复用上一个账号的租户选择。
- 切换后页面不会混用旧租户数据，且不会因切换自动清空未读消息。
- 失效租户不会继续发送请求，且不会错误清除有效登录态。
- 退出登录会清理租户上下文。
