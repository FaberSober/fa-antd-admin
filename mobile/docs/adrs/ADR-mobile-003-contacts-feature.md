# ADR：mobile 联系人功能开发与体验优化

- 状态：🟡进行中
- 日期：2026-09-21
- 范围：`fa-base` Portal 联系人只读接口、`mobile`、`fa-base-mobile`

## 背景

当前联系人页只有视觉骨架：开发环境使用 3 条 fixture，生产环境显示空态；组织架构、我的联系人、全部联系人和联系人行均未接入真实功能。

现有 `/api/base/admin/user`、`/api/base/admin/department` 属于后台接口，需要后台访问权限，不能直接作为普通移动端成员的通讯录接口。现有库也没有收藏联系人或最近联系人关系表。

设计稿和截图只作为布局、层级和交互反馈参考，其中的租户名称、联系人姓名等示例数据不得写入业务逻辑。本期将联系人定位为“当前租户内的组织通讯录”，不与 `fa-im` 的好友体系混合实现。

## 目标

- 完成当前租户内的组织架构浏览、联系人搜索和联系人详情闭环。
- 复用现有租户请求上下文、Mobile Shell 和基础组件。
- 保持接口只读、字段最小化，不新增联系人业务表。
- 处理加载、空态、错误、重试、租户切换和窄屏交互状态。

## 范围边界

- 当前版本实现组织通讯录，不实现好友申请、好友分组、联系人邀请或在线状态。
- “我的联系人”按当前用户、当前租户隔离的本机常用联系人实现；首页展示最近打开的联系人。
- 跨设备同步收藏、服务端收藏关系和 IM 会话入口留作未来版本规划。
- 不在移动端提供部门或成员的新增、编辑、删除等管理能力。

## 决策

### 1. 保留现有页面结构

- 保留 `contacts/index.vue` 的联系人首页、组织架构入口、我的联系人入口和最近联系人区域。
- 复用 `MobileShell`、`MobileSearchField`、`MobileSectionHeader` 和 `MobileEmptyState`。
- 首页未搜索时显示入口和最近联系人；输入关键词后切换为统一搜索结果。
- 组织目录使用“部门逐级进入 + 返回/面包屑”交互，不新增复杂组织架构图。

### 2. 增加 Portal 只读接口

接口放在现有 `fa-base` 模块的 Portal 域，避免直接暴露后台 Controller：

```text
GET  /api/portal/contacts/departments/tree
POST /api/portal/contacts/users/page
GET  /api/portal/contacts/users/{userId}
```

- 部门树返回部门 ID、父部门 ID、名称、成员数和子节点标识。
- 联系人列表返回 ID、姓名、头像、部门、角色信息和工作状态。
- 联系人详情按需返回账号、手机号和邮箱。
- 分页请求使用 `current`、`pageSize` 和 `query.keyword`、`query.departmentId`，返回项目通用 `TableRet` 结构。

### 3. 以服务端租户上下文为准

- 不接受客户端传入的 `tenantId` 作为查询范围。
- 继续使用 `fa-tn-tenant-id`，由服务端 `TenantContextResolver` 校验用户是否属于租户。
- 查询只返回当前租户内有效成员、有效部门和未逻辑删除数据。
- 详情接口再次校验联系人属于当前租户，避免越权读取。
- 使用 Portal DTO 白名单，不直接返回 `User` 全量字段，不暴露密码、API Token、后台权限等字段。

### 4. 本地保存常用联系人

- 以 `userId + tenantId` 作为本地存储隔离维度。
- 打开联系人详情后记录联系人摘要，首页展示前 3 条，完整列表最多保留 10–20 条。
- 租户切换后不得展示旧租户联系人。
- 如果后续确认需要跨设备同步或手动收藏，再新增独立关系表和接口。

## 开发说明

### 1. 后端接口与数据安全

- 在 `fa-base` 的 Portal 域新增薄 Controller 和独立查询 Biz/VO，不修改后台管理接口权限。
- 优先复用现有 `UserBiz`、`DepartmentBiz`、`TenantUserBiz` 和 `TenantContext`，不新增联系人表。
- 联系人查询必须同时满足当前租户成员关系有效、用户有效和部门属于当前租户。
- 联系人详情中的手机号、邮箱按确认后的字段权限返回；列表不返回敏感联系方式。
- 分页接口限制最大 `pageSize`，关键词查询在服务端完成，不把全租户用户一次性下发到移动端。

### 2. 移动端首页

- 修改 `pages/contacts/index.vue`，删除 fixture 和“功能即将开放”处理。
- 空搜索时加载最近联系人；有搜索词时请求服务端结果并显示搜索空态。
- 保留现有视觉 Token、卡片、图标和底部 Tab，不重做全局 App Shell。
- 请求失败提供明确错误和“重新加载”，不能把失败误显示为无数据。

### 3. 组织目录与详情页

- 在 `feature.ts` 和 `pages.json` 注册组织目录、联系人详情路由。
- 部门目录优先展示子部门，再展示当前部门成员；成员列表支持分页或加载更多。
- 联系人详情使用服务端真实字段；当前 `User` 没有明确职位字段，不把角色名称伪装成职位。
- 电话、邮箱操作使用 uni-app 原生能力；能力不可用时提供复制操作。

### 4. 本地常用联系人

- 使用 `uni.setStorageSync` / `uni.getStorageSync`，不引入新的状态管理方案。
- 存储 Key 必须包含用户 ID 和租户 ID，切换账号或租户时自动隔离。
- 仅保存展示摘要和联系人 ID，不保存不必要的敏感字段。
- 联系人被删除或失效时，加载列表时忽略异常记录。

### 5. 交互和可用性

- 搜索输入停止约 300ms 后请求；快速连续输入时旧请求结果不能覆盖新结果。
- 主要点击区域保持现有 `var(--fa-size-touch)` 以上，H5 及 App 适配至少 44–48px 触控目标。
- 长租户名、长联系人名、长部门名使用省略或换行策略，避免横向溢出。
- 列表底部预留 Tab Bar 和安全区空间，最后一项不能被遮挡。
- 亮色、暗色、加载、空态、错误和禁用状态沿用现有主题变量。

## 实施顺序

1. 确认手机号、邮箱可见范围，以及“我的联系人”的本地常用语义。
2. 完成 Portal DTO、部门树、联系人分页和联系人详情接口。
3. 新增移动端 API/types，并接入联系人首页。
4. 新增组织目录页和联系人详情页。
5. 接入本地常用联系人、电话/邮箱操作和租户切换清理。
6. 补齐搜索竞态、分页、空态、失败重试和窄屏交互。
7. 完成后端租户隔离测试、移动端类型检查和三端关键流程验证。

## 验收标准

- 普通租户成员无需后台访问权限即可查看当前租户通讯录。
- 无法通过修改租户请求头或联系人 ID读取其他租户数据。
- 首页、组织目录、联系人详情和返回路径完整可用。
- 支持姓名、账号、部门关键词搜索，分页和搜索无结果状态正确。
- 加载失败可重试，错误状态不会伪装成空列表。
- 租户切换后不会残留旧租户联系人或本地常用记录。
- 不再依赖联系人 fixture，生产环境展示真实接口结果。
- 页面在约 320–430 CSS 像素宽度下无横向溢出，底部内容不被 Tab Bar 遮挡。
- 完成 `pnpm --dir mobile type-check`，并运行受影响后端测试或最小模块编译检查。

## 非目标与后续

- 本期不新增数据库表、DDL、联系人管理 CRUD 或后台管理页面。
- 本期不实现好友申请、好友分组、在线状态、消息实时推送和跨设备收藏同步。
- 当本地常用联系人无法满足跨端使用，或数据量导致本地方案受限时，再增加服务端收藏关系和专用索引。
