# ADR：mobile 页面生命周期与静默刷新

- 状态：👀待确认

- 范围：`mobile`、`fa-base-mobile`、`fa-core-mobile`
- 关联：`ADR-mobile-002-ui-app-shell.md`、`ADR-mobile-004-mine-feature.md`
- 当前进度：已完成现状分析和执行方案，等待确认后开发

## 背景

当前四个主页面在 `onShow` 中执行完整加载，Tab 切换使用 `uni.reLaunch`，返回上级页面也会重新触发整页 loading。页面数据主要保存在组件状态中，导致页面反复进入时出现闪烁、列表清空和重复请求。

## 目标与范围

- 首次进入页面时允许展示完整 loading。
- 再次进入页面时优先展示已有数据，再后台静默刷新。
- 统一处理首页、消息、联系人、我的及其子页面返回场景。
- 普通 Tab 切换不再触发整页销毁和重建。
- 保证用户、租户和页面数据不会互相串用。

## 功能开发说明

### 1. 首次加载与再次进入策略

- 页面状态统一区分 `initial-loading`、`ready`、`refreshing` 和 `error`。
- 没有缓存数据时展示页面 loading。
- 已有缓存数据时直接展示旧数据，后台执行静默刷新。
- 静默刷新失败时保留旧数据，并使用非阻塞提示。

### 2. 页面数据缓存

- 用户、租户、消息和联系人数据由 Pinia Store 持有。
- 页面组件只保留筛选、编辑和临时交互状态。
- 缓存按用户 ID 和租户 ID 隔离。
- Store 保留最近一次成功数据和刷新状态，不把失败结果覆盖成空数据。

### 3. 静默刷新与请求去重

- `onShow` 只负责触发统一刷新策略，不直接重置页面状态。
- 首次请求允许阻塞页面，后续请求使用后台刷新状态。
- 同一数据已有请求进行时复用或忽略重复请求。
- 手动刷新可以绕过缓存时间，但不清空当前内容。
- 使用请求版本或租户标识，避免旧请求覆盖新数据。

### 4. 主 Tab 页面保活

- 保留现有自定义 Tab Bar 的视觉和交互。
- 增加认证后的主页面容器，主 Tab 通过受控视图切换。
- 普通 Tab 切换不再使用 `uni.reLaunch`，保留列表、筛选和滚动状态。
- 登录、退出登录和必要的上下文重置仍允许使用完整重载。
- 账号、资料、关于等二级页面继续使用普通页面导航。

### 5. 主页面适配

- “我的”返回时保留资料卡，后台刷新用户和租户信息。
- 首页、消息和联系人返回时保留已有内容，再静默更新。
- 消息已读、资料保存和手动刷新成功后主动更新对应 Store。
- 不因普通 `onShow` 清空列表、重置筛选或显示整页 loading。

### 6. 登录和租户上下文隔离

- 退出登录时清理用户、租户和业务页面缓存。
- 切换账号时不得复用上一个账号的数据。
- 切换租户时使旧租户业务数据失效，再加载目标租户数据。
- 租户切换期间不展示无法确认归属的旧数据。

### 7. 回归验证

- 验证首次进入“我的”显示 loading，数据成功后正常展示。
- 从“我的”进入账号与安全再返回，不出现整页 loading。
- 在首页、消息、联系人和我的之间反复切换，不出现页面闪烁或内容清空。
- 验证静默刷新失败、手动刷新、退出登录和租户切换场景。
- 验证约 320–430 CSS 像素宽度下内容不溢出。

## 决策

- 页面缓存与刷新策略由移动端基础层统一定义，不在单个页面重复实现首次加载判断。
- 服务端数据仍是最终准源，缓存只用于改善再次进入时的展示体验。
- 普通页面进入使用静默刷新；认证边界和租户上下文变化可以执行完整重置。
- 本 ADR 第一阶段不实现 WebSocket 实时刷新，不新增后端接口。

## 实施顺序

1. 确认页面生命周期状态和缓存失效规则。
2. 扩展现有 Auth、Tenant、Message Store，并补充联系人页面 Store。
3. 抽取统一的静默刷新、请求去重和错误处理逻辑。
4. 建立主 Tab 页面容器，替换普通 Tab 的 `uni.reLaunch`。
5. 适配首页、消息、联系人、我的及子页面返回逻辑。
6. 完成账号切换、租户切换和退出登录的数据清理。
7. 执行类型检查和人工回归验证。

## 验收标准

- 每个主页面首次进入时可以展示 loading。
- 已加载页面再次进入时不显示整页 loading，旧数据立即可见。
- 后台刷新成功后页面内容自动更新。
- 后台刷新失败不会清空已有数据。
- 普通 Tab 切换不销毁主页面状态。
- 账号和租户切换不会混用旧数据。
- `pnpm --dir mobile type-check` 通过。

## 非目标

- 不新增 WebSocket 或厂商推送能力。
- 不引入第三方页面缓存或状态管理依赖。
- 不修改业务接口返回结构。
- 不在本 ADR 中处理跨租户未读数聚合接口。
