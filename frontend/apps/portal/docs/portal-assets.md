# Portal 静态资源规范

> 适用范围：`frontend/apps/portal` 及其 Feature
> 更新日期：2026-07-23

## 1. 基本原则

- Feature 私有资源放在对应 Feature 的 `assets/` 目录；跨 Feature 公用且稳定的资源放在 `public/`。
- 页面通过模块导入或 `import.meta.env.BASE_URL` 引用资源，不硬编码 `/assets/**` 根路径。
- 不从 Admin Feature、Admin 全局样式或 Admin 资源聚合入口导入文件。
- 只有首屏关键视觉资源可以预加载，其他图片和视频按需加载。

## 2. 图片

- 内容图片优先提供 AVIF，其次 WebP；需要兼容或透明度时可以补充 PNG。
- 列表缩略图建议提供 480、768、1280 三档，并通过 `srcset`/`sizes` 选择。
- 首屏主视觉建议不超过 200 KB，单张图片不得超过 300 KB；非首屏图片默认 `loading="lazy"`。
- 必须声明 `width`、`height` 或稳定的 `aspect-ratio`，避免加载时布局位移。
- 有内容含义的图片必须提供准确 `alt`；纯装饰图片使用空 `alt`。
- 不把大图编码为 Base64 写入 TS、TSX 或 CSS。

## 3. 视频

- 默认不自动播放带声音的视频；背景视频必须静音、可暂停，并提供静态封面。
- 首屏不直接下载完整视频文件，优先使用封面和用户触发后加载。
- 推荐 MP4/H.264 作为基础格式，可按部署环境补充 WebM。
- 大文件应放对象存储或 CDN，不随 Portal JavaScript Chunk 打包。

## 4. 下载文件

- PDF、白皮书、安装包等下载资源应使用可长期缓存的版本化文件名。
- 链接旁展示文件类型和大小；跨域下载需要明确来源。
- 不在前端暴露内部路径、临时凭证或未经授权的对象存储地址。
- 需要登录或授权的文件必须通过后端签发短时地址，不能只依赖前端隐藏入口。

## 5. 字体与图标

- 默认使用系统字体栈。
- 品牌字体只允许 WOFF2 子集，并设置 `font-display: swap`。
- 图标优先使用仓库内独立 SVG 或 CSS，不整包引入图标库。
- SVG 应移除编辑器元数据、脚本和无用节点；用户上传 SVG 必须经过服务端安全处理。

## 6. 合入检查

- 检查文件尺寸、格式、尺寸声明和懒加载策略。
- 检查资源路径在 `/portal/` basename 下可用。
- 检查资源没有引入 Admin 运行时或跨 Feature 私有文件。
- 在桌面和移动端观察布局位移、清晰度和触控行为。
- 生产构建会自动执行 gzip 后 JS/CSS、单张图片和预渲染 HTML 门禁；结果写入 `dist/build-report.json`。
- 当前 Portal 没有内容位图，只有 0.49 KiB SVG favicon；后续新增位图仍必须满足本规范和自动预算。
- Vite 导入资源使用 hash 文件名；最终 `Cache-Control`、gzip/Brotli 和 CDN 行为由 Phase 5 的发布链路统一配置。
