# 移动页面 A/B/C 适配矩阵

## 目的

本矩阵冻结首期移动化边界，避免将“手机端 Admin”理解成桌面页面的全量响应式复制。分类依据包括使用频率、单手操作可行性、信息密度、字段数量、数据风险和现有组件复杂度。

## 分类定义

| 等级 | 定义 | 实施原则 |
|---|---|---|
| A | 高频、低到中等复杂度，天然适合手机操作 | 优先进入 M1～M4 |
| B | 有移动价值，但必须重新设计信息架构或交互 | 逐个业务评审后实施 |
| C | 高信息密度或强桌面交互 | 首期保留 Admin 桌面端 |

## A 类：首期优先

| 能力/现有页面 | H5 目标 | 计划阶段 | 备注 |
|---|---|---|---|
| 登录 | `/login` | M1/M3 | 独立移动表单，不复用桌面登录背景 |
| 工作台 | `/app/home` | M3 | 只展示高频入口和轻量统计 |
| 个人基本信息 | `/app/me` | M3 | 首期只读，编辑按字段再评估 |
| 租户切换 | AppShell | M3 | 使用 ActionSheet/Picker |
| 消息中心 | `/app/messages` | M4 | 首个真实业务试点 |
| 更新密码 | `/app/me/security` | M4 以后 | 单列全屏表单 |
| 系统公告/新闻只读 | `/app/notices` | M4 以后 | 先读后管，编辑保留桌面端 |
| 简单状态确认/待办 | 业务 Feature | M4 以后 | 必须有后端数据范围保护 |
| Student CRUD | Demo Feature | M4 技术切片 | 仅验证开发模板，不算生产试点 |

## B 类：重新设计后实施

| Admin 领域/页面 | 移动化建议 | 主要问题 |
|---|---|---|
| 用户管理 | 搜索、详情、启停和少量字段编辑 | 字段多、角色/部门选择复杂 |
| 部门管理 | 树浏览 + 节点详情 | 树编辑和拖动不适合小屏 |
| 角色权限 | 角色查看和用户关联 | 大型权限树应保留桌面 |
| 字典/地区 | 搜索、详情和简单维护 | 多层树及批量维护复杂 |
| 定时任务 | 状态查看、启停和执行确认 | Cron 编辑、日志分析偏桌面 |
| 告警 | 列表、详情、确认/关闭 | 需要明确状态流和数据权限 |
| 租户/租户用户 | 查看、启停、邀请 | 管理风险较高，需强权限确认 |
| 附件管理 | 我的文件、上传和预览 | 批量管理、目录操作需重构 |
| AI Agent | 列表、运行状态、测试入口 | 编辑器和 Workflow 保留桌面 |
| 知识库 | 列表、文档状态、简单导入 | 分段、命中测试和批量操作复杂 |
| NL2SQL | 会话和结果摘要 | 元数据、关系和审计页面信息密集 |
| Vision 项目 | 项目列表、进度和统计摘要 | 数据集版本、训练配置需拆分 |
| 地图业务 | 定位、轻量浏览和单点选择 | 路由编辑和复杂图层不适合小屏 |

B 类页面进入 Roadmap 前必须产出独立交互稿和移动字段裁剪清单。

## C 类：首期不移动化

| Admin 页面/能力 | 原因 |
|---|---|
| AI Workflow 节点编辑 | 拖拽画布、配置面板和连线操作依赖大屏 |
| Vision 标注 | 图像画布、快捷键和标注工具依赖桌面输入 |
| 3D、复杂地图和可视化编辑 | GPU、视口和多面板交互成本高 |
| Druid、Redis、服务器和日志监控 | 信息密度高且操作风险大 |
| 代码生成器 | 配置项多、生成结果和文件操作复杂 |
| 大型可编辑表格、Grid 和 Table Edit | 横向字段和批量编辑不适合手机 |
| TinyMCE、Office、复杂文档编辑 | 键盘、工具栏和内容区需要大屏 |
| 角色权限树全量配置 | 大型树选择、半选和批量权限操作复杂 |
| 系统全局配置 | 高风险且字段多，应保留桌面端 |

## 首期 MVP 范围

MVP 包含：

- 账号密码登录、退出和会话恢复。
- 工作台、个人中心和租户切换。
- `scope=2` 路由权限。
- 个人消息中心。
- Student 移动 CRUD 技术模板。

MVP 不包含：

- 外部 SSO。
- 消息删除和任意消息详情接口。
- Admin 页面直接嵌入 H5。
- B/C 类页面的批量迁移。
- PWA、离线缓存和 Push。

## 新页面分级问卷

新增移动页面前回答：

1. 用户是否需要在离开电脑时完成该操作？
2. 核心任务能否在 3 个主要步骤内完成？
3. 首屏是否可以压缩到 5 个以内关键字段？
4. 是否依赖横向表格、拖拽、画布、快捷键或多窗口？
5. 是否包含批量、删除、授权或系统配置等高风险操作？
6. 后端是否按当前用户和租户限制数据范围？
7. 是否具备可自动化的移动端验收路径？

第 4 项为“是”通常归入 C；第 5、6 项未解决时不能进入 A。
